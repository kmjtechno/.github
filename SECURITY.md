# Security Policy

KMJ TECHNO and project maintainers treat vulnerability reports as sensitive engineering information.

## Report a vulnerability privately

For public KMJ repositories, open the **Security → Report a vulnerability** flow where available. Do **not** open a public issue containing exploits, credentials, user data, access tokens, private endpoints or reproducible attack instructions. If a repository does not offer private vulnerability reporting, contact its maintainers through an existing verified private project channel.

Identify the affected repository, release or commit, prerequisites, impact and a safe reproducible outline. Share proof-of-concept details only through the private reporting channel.

## Scope and supported versions

Security support is product-specific. Use the affected repository's **Releases**, README and security advisories to determine the supported versions. A development branch, preview or experimental feature must not be assumed production-ready or supported.

Maintain least-privilege access, rotate exposed secrets and avoid running unverified scripts. Project maintainers coordinate assessment and remediation; reporting does not guarantee a particular response or disclosure date.

For general company information, visit [KMJ TECHNO](https://kmjtechno.com).
